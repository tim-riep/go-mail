# Auftrag 16: Test auf zwei Maschinen nach 9.1 (`scripts/two-host-test.sh`)

Welle 4, nach Auftrag 15. Feste Vorgaben: `docs/tasks/00-vorgaben.md`. Grundlage: `docs/PLAN.md` 9.1 („Bedingungen für den Netzbetrieb“: NFSv4 mit Sperrunterstützung, POSIX-Satzsperren/OFD, getrennte Betriebssystembenutzer in der Gruppe `gomail`, Rechte 0660/2770, Schlüsselspeicher 0600 nur lokal, Testsperre beim Start), 10.2 (Abnahme), `docs/DECISIONS.md` D70, `internal/store/lock_*.go`, `cmd/gomail-server/main.go`, `cmd/gomailctl/main.go` (Rollensperren aus Auftrag 15). In dieser Umgebung steht keine zweite Maschine und kein NFSv4 zur Verfügung: das Skript wird vorbereitet und lokal so weit geprüft, wie es ohne NFS geht; M1 gilt dann für Punkt E „bedingt erreicht“ (ORCHESTRATION/Abschlussbericht).

## Umfang
1. `scripts/two-host-test.sh` (POSIX sh oder bash, nur Standardwerkzeuge): Parameter `--server-host`, `--client-host` (SSH-Ziele), `--export` (NFS-Export auf dem Server), `--mount` (Mountpunkt auf dem Client), `--pin`, `--witness`; Schritte: (a) Voraussetzungen prüfen (NFSv4-Mount mit `vers=4`, Gruppe `gomail` auf beiden Seiten, getrennte Benutzer, `umask`), (b) Datenverzeichnis auf dem Server anlegen (`gomail-server init`, Rechte 2770/0660 prüfen), (c) Sperrtest: Server hält `locks/server`, Client prüft über NFS, dass die Sperre wirksam ist (`gomailctl` startet nur dann; Gegenprobe: ohne Server verweigert der Client; zweiter Server auf dem Client-Host verweigert), (d) Ende-zu-Ende: Registrierung, Postfach, Mail über SMTP an den Server, `sync`/`list`/`read` auf dem Client, `share` mit einem zweiten Benutzer auf dem Client-Host, Log-Kopf mit Zeuge; (e) Nachweis: keine privaten Schlüssel im Export (`find` nach 0600-Dateien und nach `keystore`), kein Klartext (grep nach dem Betreff im Export), Rechte aller Dateien; (f) Protokoll als Markdown mit allen Befehlen und Ausgaben unter `--out`. Jeder Schritt bricht bei Fehler ab (`set -eu`), Ausgaben nennen nur IDs und Pfade.
2. Lokale Prüfung ohne NFS: `scripts/two-host-test.sh --local` führt (b), (c) mit zwei Betriebssystembenutzern oder, falls nicht möglich, zwei Prozessen desselben Benutzers (dann mit deutlicher Warnung „kein Nachweis nach 9.1“) und (d)–(f) auf einer Maschine aus; `go test ./internal/e2e -run TestTwoHostScript` ruft das Skript im lokalen Modus auf (übersprungen, wenn `sh` oder die Programme fehlen).
3. `docs/RUNBOOK.md` bekommt einen Abschnitt „Zwei Maschinen“ (Auftrag 19 ergänzt ihn; hier nur die Aufrufe und Voraussetzungen).

Fertig: `shellcheck`, falls vorhanden, ohne Fehler; `bash -n`; lokaler Modus läuft durch; `go test ./internal/e2e`.
